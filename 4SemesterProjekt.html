PROJEKTBESKRIVELSE – 4. SEMESTER

PROJEKTETS FORMÅL

Norlys ønsker et bedre overblik over ældre og inaktive eller belastede virtuelle maskiner i deres Azure tenant, så de kan identificere hvilke virtuelle maskiner der bør skaleres op eller ned, stoppes eller fjernes. Målet er at optimere driften og reducere unødvendige omkostninger gennem bedre udnyttelse af ressourcer.

I samarbejde med Norlys vil vi udvikle et webbaseret dashboard der giver overblik over deres virtuelle maskiner i Azure. Formålet er at skabe overblik over forbruget, belastning og potentielle fejlscenarier, samt at sende automatiske alerts til relevante medarbejdere ved uventede hændelser, for eksempel unormalt højt RAM-forbrug, nedbrud eller afvigelser i forventede ressourceforbrug.

Norlys har efterspurgt en løsning, hvor design trækker inspiration fra Spotify Backstage og ServiceNow og udnytter moderne cloud-native teknologier. De har foreslået at anvende Azure Functions og Azure Container Apps til backend og frontend, samt Microsoft Authentication (MS Auth) til login. Desuden nævnte de brug af Bicep som værktøj til at definere og versionere infrastrukturen som kode.

TEKNOLOGI OG ANVENDELSE AF VALGFAG

UI/UX

I projektet arbejder vi på at optimere brugeroplevelsen, så det bliver let at navigere og hurtigt giver et ønsket overblik og relevant information. Vi udarbejder wireframes og mockups, som skal give grundlaget for frontend-udviklingen. Vi anvender principper fra brugercentreret design, hvor vi løbende inddrager virksomheden for at sikre, at løsningen matcher deres ønsker og arbejdsgange.

Der lægges vægt på intuitiv og effektiv brug. Designet skal understøtte dette gennem kontrast, læsbarhed og visuel konsistens med inspiration fra løsninger som Spotify Backstage og ServiceNow.

WEBUDVIKLING & FRONTEND-TEKNOLOGIER

Vi bruger React til at udvikle en moderne og brugervenlig grænseflade. Der anvendes komponentbaseret arkitektur, og vi fokuserer på performanceoptimering og responsive designprincipper. Autentificering håndteres via Microsoft Authentication (Azure AD), som gør det muligt at beskytte systemet med virksomhedens eksisterende brugerkonti.

Der arbejdes med begreber som CSR vs. SSR, især i forhold til hvordan løsningen bedst hostes i Azure. Frontenden deployes via Azure Container Apps, og der undersøges hvordan dette påvirker indlæsningstider og brugeroplevelse.

BACKEND-UDVIKLING OG API-DESIGN

Backend’en udvikles med Azure Functions i en serverless og event-baseret arkitektur, som reagerer på målinger og triggers fra Azure Monitor. Den evaluerer data og udløser automatiske handlinger som fx alerts. Vi undersøger brug af API-design, autorisering (OAuth2 + tokens), samt hvordan alerts bedst sendes som notifikationer via e-mail, push-notifikationer eller webhook-integrationer.

CI/CD-pipelines anvendes til automatisk at bygge og udrulle backend-koden, så funktionalitet løbende kan testes og opdateres.

CYBER SECURITY

Vi arbejder med OAuth2-flow og adgangsstyring via Azure AD. Dette sikrer, at kun autoriserede brugere kan tilgå systemet og se sensitive data. Vi undersøger principper fra Zero Trust Architecture, og implementerer ”Least Privilege” og betinget adgang til API’er og cloud-services.

Derudover forholder vi os til GDPR, logning, overvågning og beskyttelse af potentielt følsomme data.

AUTOMATISERING OG SCRIPTING

Projektet forventes også at inddrage scripting — fx til automatiseret dataindsamling fra Azure Monitor eller oprettelse af testdata. Dette kan ske via PowerShell, Bash eller Python.

Vi anvender Infrastructure as Code (IaC) via Bicep, hvor hele projektets Azure-infrastruktur defineres som kode. Dette gør det nemt at reproducere, ændre og versionere opsætningen.

APPUDVIKLING

Et teammedlem med appudvikling som valgfag har mulighed for at udvikle en mobil companion app. Appen kan vise alerts og sende push-notifikationer direkte til brugeren — som et supplement til dashboardet.

LÆRINGSMÅL OG FOKUS

Projektet giver mulighed for at lære og arbejde med teknologier som Azure Functions, Bicep, OAuth2-flow, cloud-deployment og sikkerhedsprincipper. Derudover giver projektet erfaring med CI/CD, frontendoptimering, monitoreringsstrategier, API-design og integration mellem cloud-services.

Vi prioriterer virkelighedsnære løsninger, tæt dialog med virksomheden og løbende validering af funktionalitet og brugeroplevelse.

Motivation og fremgang i gruppen

Fra processtart til slut – refleksion

I starten af semestret

I projektets opstart var gruppen samlet om en fælles vision om at udvikle et fuldt fungerende cloud-native VM-dashboard til Norlys. Vi udarbejdede et solidt teoretisk fundament med use cases, BMC, klassediagrammer og et komponentdiagram, der visualiserede systemets sammenspil. Der var optimisme om backendens Clean Architecture-struktur og forventning om hurtig fremdrift. Vi aftalte ugentlige torsdagsmøder for at sikre struktur.

Midt i projektet

Som projektet skred frem, havde frontend god fremdrift, men backend-delen ramte flere integrationsproblemer:

  • Token-flows og Azure AD authentication
  • Manglende kobling mellem Domain/Application → Functions
  • Usikkerhed omkring Managed Identity vs. Service Principal
  • Udfordringer med Azure Monitor adgang
  • Lokal backend uden reel forbindelse til Azure

Jeg og Pascal havde vanskeligheder med alignment på tværs af tekniske tilgange, og fordi vi arbejdede online på forskellige tidspunkter, hvilket forsinkede udviklingen. Frontend efterspurgte løbende backend-status: “vi mangler klar opdatering på timeline”.

PO-møder hver tredje uge gjorde det tydeligt, at backend ikke fulgte med frontendens tempo. Dette påvirkede gruppens motivation betydeligt.

Mod slutningen

For at forbedre koordineringen udvidede vi mødestrukturen til to ugentlige møder (tirsdag og torsdag). Det blev klart, at backend-v1 ikke kunne reddes:

  • Uens environment-variables
  • Forkert authorizationLevel i Azure Functions
  • API’et ramte forkerte Azure Monitor-endpoints
  • Lagene i Clean Architecture var ikke bundet rigtigt sammen

Markus tog initiativ til Backend-v2 — en ny, minimalistisk arkitektur med fokus på Azure-integration. Jeg begyndte at samarbejde tættere med Markus for at forstå strukturen, hvilket gav mig nyt overblik.

Backend-v2 leverede:

  • Simpelt, stabilt MetricsController
  • Korrekt token-flow og Azure AD scope
  • Rigtige Azure VM-data
  • En brugbar API base URL til frontend

Afslutning og MVP-leverancer

Til trods for udfordringer leverede gruppen et MVP der opfyldte PO’ens vigtigste krav:

  • Fuld API-integration mellem frontend og Azure Functions
  • Tænd/sluk af virtuelle maskiner
  • Alerts til mail og telefon
  • Stabil pipeline fra Azure Monitor → Backend → Frontend
  • Visualisering af VM-status, performance og driftsdata

Vi nåede ikke alt, men de vigtigste kernefunktioner var implementeret.

For mit vedkommende har projektet været en vigtig læringsproces — især inden for disciplin og struktur i backend-udvikling, Azure-sikkerhed og API-integration. Gennem dialogen med Markus fik jeg bedre forståelse af backend-arkitektur og udviklede mig markant teknisk.
