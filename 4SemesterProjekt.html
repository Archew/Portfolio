PROJEKTBESKRIVELSE – 4. SEMESTER

PROJEKTETS FORMÅL

Norlys ønsker et bedre overblik over ældre og inaktive eller belastede virtuelle maskiner i deres Azure-tenant, så de kan identificere hvilke virtuelle maskiner der bør skaleres op eller ned, stoppes eller fjernes. Målet er at optimere driften og reducere unødvendige omkostninger gennem bedre udnyttelse af ressourcer.

I samarbejde med Norlys vil vi udvikle et webbaseret dashboard der giver overblik over deres virtuelle maskiner i Azure. Formålet er at skabe overblik over forbruget, belastning og potentielle fejlscenarier, samt at sende automatiske alerts til relevante medarbejdere ved uventede hændelser, for eksempel unormalt højt RAM-forbrug, nedbrud eller afvigelser i forventede ressourceforbrug.

Norlys har efterspurgt en løsning, hvor design trækker inspiration fra Spotify Backstage og ServiceNow og udnytter moderne cloud-native teknologier. De har foreslået at anvende Azure Functions og Azure Container Apps til backend og frontend, samt Microsoft Authentication (MS Auth) til login. Desuden nævnte de brug af Bicep som værktøj til at definere og versionere infrastrukturen som kode.

TEKNOLOGI OG ANVENDELSE AF VALGFAG

UI/UX

I projektet arbejder vi på at optimere brugeroplevelsen, så det bliver let at navigere og hurtigt giver et ønsket overblik og relevant information. Vi udarbejder wireframes og mockups, som skal danne grundlaget for frontend-udviklingen. Vi anvender principper fra brugercentreret design, hvor vi løbende inddrager virksomheden for at sikre, at løsningen matcher deres ønsker og arbejdsgange. Der lægges vægt på, at brugeroplevelsen er intuitiv og effektiv, og at designet understøtter dette gennem kontrast, læsbarhed og visuel konsistens, med inspiration fra løsninger som Spotify Backstage og ServiceNow.

WEBUDVIKLING & FRONTEND-TEKNOLOGIER

Vi bruger React til at udvikle en enkel, moderne og brugervenlig brugergrænseflade. Der anvendes komponentbaseret arkitektur, og vi fokuserer på performance-optimering og responsive designprincipper. Autentificering håndteres via Microsoft Authentication (Azure AD), som gør det muligt at beskytte systemet med virksomhedens eksisterende brugerkonti. Der arbejdes med begreber som CSR vs. SSR, især i forhold til hvordan løsningen bedst hostes i Azure. Frontenden deployes via Azure Container Apps, og vi undersøger, hvordan det påvirker indlæsningstider og brugeroplevelse.

BACKEND-UDVIKLING OG API-DESIGN

Backend’en udvikles med Azure Functions i en serverless og event-baseret arkitektur, som reagerer på målinger og triggers fra Azure Monitor. Den evaluerer data og udløser automatiske handlinger som fx alerts. Vi undersøger brug af API-design, autorisering (OAuth2 + tokens), samt hvordan alerts bedst kan sendes som notifikationer via fx e-mail, push-notifikationer eller webhook-integrationer. CI/CD-pipelines bruges til automatisk at bygge og udrulle koden, så systemet nemt kan testes og opdateres.

CYBER SECURITY

Vi arbejder med OAuth2-flow og adgangsstyring via Azure AD. Dette sikrer, at kun autoriserede brugere kan se og reagere på data. Vi forventer at undersøge principper fra Zero Trust Architecture, samt sikre vores API’er og cloud-deployments mod uautoriseret adgang. Derudover forholder vi os til GDPR, logning og beskyttelse af eventuelle personfølsomme data.

AUTOMATISERING OG SCRIPTING

Projektet forventes også at inddrage scripting – fx til automatiseret dataindsamling fra Azure Monitor eller oprettelse af testdata. Dette kan ske via PowerShell, Bash eller Python. Desuden anvendes Infrastructure as Code (IaC), hvor vi med Bicep definerer hele den nødvendige Azure-infrastruktur (fx hvilke container apps og functions der skal oprettes, og hvordan de skal forbindes). Dette gør det nemt at reproducere og vedligeholde opsætningen.

APPUDVIKLING

Der er mulighed for, at et teammedlem med appudvikling som valgfag udvikler en enkel mobil companion app. Denne app kan give overblik over aktuelle alerts og sende push-notifikationer direkte til brugeren. Appen vil fungere som et supplement til det webbaserede dashboard og give virksomheden øget fleksibilitet.

LÆRINGSMÅL OG FOKUS

Projektet giver mulighed for at lære og anvende flere teknologier, vi endnu ikke mestrer, bl.a. Azure Functions, Bicep, OAuth2-flow, samt cloud-deployment og sikkerhedsprincipper. Det giver også mulighed for at arbejde med CI/CD, frontendoptimering og monitoreringsstrategier. Vi prioriterer virkelighedsnære løsninger, løbende samarbejde med virksomheden og en løbende validering af funktionalitet og brugeroplevelse.

Midt i projektet

Frontend havde fremdrift, men backend ramte integrationsproblemer ...

  • Azure AD tokenflows
  • Manglende kobling mellem Domain/Application → Functions
  • Managed Identity vs Service Principal usikkerhed
  • Manglende adgang til Azure Monitor
  • Lokal backend uden reel Azure-forbindelse

Mod slutningen

Vi udvidede mødestrukturen til tirsdag + torsdag ...

Backend-v1 havde fundamentale problemer:

  • ukonsistente environment-variables
  • forkert authorizationLevel
  • endpoints ramte ikke Azure Monitor korrekt
  • Clean Architecture var ikke forbundet

Markus opbyggede Backend-v2, som var minimalistisk og stabil ...

Jeg arbejdede tæt sammen med Markus mod slutningen ...

Backend-v2 gav os:

  • stabil MetricsController
  • korrekt AD scope / token-flow
  • rigtige VM-data fra Azure
  • API base URL som frontend kunne bruge

Afslutning og MVP

Vi leverede et MVP med:

  • API-integration via Azure Functions
  • Tænd/sluk VM funktioner
  • Alerts til mail/telefon
  • Stabil pipeline fra Azure Monitor → Backend → Frontend
  • Dashboard med performance-data

Projektet nåede ikke alle feature-mål, men leverede alle kernefunktioner PO efterspurgte.

Jeg lærte især om disciplin, backend-arkitektur, Azure-sikkerhed og API-integrationer. Samarbejdet med Markus var centralt for at forstå strukturen i Backend-v2 og komme videre.
